# Безопасность

## Модель угроз

Brain запускает агентные CLI, даёт им доступ к файловой системе и хранит
секреты. Существенны три класса проблем:

1. **Утечка данных в публичный срез.** Репозиторий собирается скриптом
   `brain-publish` из приватного дерева. Ошибка в правилах отбора выносит
   наружу рабочие материалы. Схема отбора сейчас fail-open — страница
   попадает в срез, пока её явно не исключили.
2. **Выполнение произвольного кода.** Команды собирают shell-строки и
   запускают агентов. Точка внедрения — имя роли, идентификатор задачи или
   значение из файла конфигурации, попавшее в командную строку без
   экранирования.
3. **Обращение с секретами.** `.secrets/` копируется в облако командой
   `brain-backup`. Промах с целевым аккаунтом означает передачу ключей
   постороннему.

## Как сообщить

Приватно, через [приватное сообщение об уязвимости][advisory].

Не заводите публичный issue, если находка позволяет получить чужие данные
или выполнить код. Публикация до исправления даёт готовую инструкцию.

[advisory]: https://github.com/Blqd/brain/security/advisories/new

Полезно приложить: минимальное воспроизведение, версию, оценку того, что
именно достижимо — чтение файлов, запись, запуск процессов.

## Что уже известно

Эти вещи известны и не требуют отдельного сообщения:

- Файлы `tests/cases/*.sh`, запущенные напрямую в обход `tests/run.sh`,
  работают по боевому `BRAIN_PATH` и уничтожают рабочие данные. Запускать
  тесты следует только через раннер.
- Отбор страниц для публикации построен на шаблоне с вычитанием денилиста,
  то есть fail-open по своей природе. Переход на явную пометку запланирован.

## Границы

Brain рассчитан на одного пользователя на его собственной машине.
Многопользовательская изоляция, контроль доступа и защита от локального
администратора в задачи не входят — сообщения об их отсутствии не являются
уязвимостями.

Вознаграждения за находки нет.
